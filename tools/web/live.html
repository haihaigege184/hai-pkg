怎么读这张表：
· 看到 PUT/POST 且路径是 /hai/lib/tokenm.json → 端确实把 CK 送回中枢了，会立刻入库并同步给其他设备。
· 只有 GET → 端只是在取配置，「扫码得到的 CK 目前留在端自己身上」， 需要靠下面的外部中转把凭据换取请求接过来。

外部中转 · 凭据旁路

…
原理：PG 的 tokenm.json 里 open_api_url 指向「网盘换 token 的接口」， 端会把扫码/刷新得到的凭据 POST 过去 —— 这一步本来直连第三方，中枢看不见。
改写开启后，该地址指向 /gw/ali/token：原样透传给真正的上游（端的功能不受影响）， 同时把请求与响应里的凭据截下来入库 → 其余设备下一轮拉配置（约 15~30 秒）就自动生效。

WebDAV 端点 · 端主动备份通道

…
端上的 CK 就是一个明文文件：/storage/emulated/0/TV/.<渠道>_user.pg （例：夸克 = .quark_user.pg）。这个目录属外置存储、非私有目录 —— 电视上装个文件管理器、打开「显示隐藏文件」，就能看 / 拷走 / 删掉 / 替换。
WebDAV 这边的文件名与它一一对应（去掉 _user.pg、换成 .json）， 所以「同步 CK」本质就是「同步这些文件」：
 · 上行（端 → 中枢）：网盘 CK 类只读不写 —— quark / uc / baidu / 115 / 123 / 189 / aliyun / pikpak / thunder 这些 .json 的 PUT 次数实测为 0。端只写过三类： 播放进度 playprogress.json（播放中约每分钟一次）、 连通测试 connection_test.json（填地址时一次）、 观影站点 cookie cookie_guanying.json（登录态变化时一次）。
   → 端上扫码得来的网盘 CK 不会自动送上来，必须人工导入一次。
 · 下行（中枢 → 端）：端在打开对应网盘设置 / 重新保存 WebDAV 配置 这一类时机来取一批（实测 quark.json 取过 10 次、aliyun.json 7 次、 baidu.json 6 次、uc.json 5 次），取到 200 就用云端内容覆盖本地 → 往保险库写一次 CK，端下次来取就写进它自己的落盘文件（见下表「回填」）。
 · ⚠️ 覆盖风险：云端一旦有值，端取走后会盖掉本地那份。 所以保险库里存的必须是完整有效的 CK —— 半截或过期的会把端上刚扫码登录好的状态冲掉。 如无把握，宁可不填。
 · 怎么开：在 OK影视 的「网盘及弹幕配置」→ WEBDAV 缓存网盘信息 里填 …（账号密码随便填，中枢不校验），再做一次「备份 / 缓存」。
