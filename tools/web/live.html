查什么：导航页（https://fty.888484.xyz/）是这批站源的发布台 —— 作者换域名、换接口路径，第一时间改的就是它。每次「上游同步」都会抓一次并与上次快照比对：
① 站源域名有无变化（谁换了域名）；② 接口地址有无变化（同一域名的路径变了，或整个地址换了）； ③ 新增 / 消失的站源。
同时记录每个上游源最近一次成功抓取的地址：站方自己 302 换路径也能被发现。
导航页里的当前地址会自动排到同名上游源的候选最前面（写在 UPSTREAM_FEEDS[].nav 里绑定）， 所以作者一换域名，下一轮同步就用上了，不必等我们改配置。

「加入」按钮：点一下就把这个站源加进 PG 包，端上「接口选择」页里能直接用。 加入要过三道闸，任何一道不过就不加：
① 能力闸（静态）—— 本包 pg.jar 里必须有对应的解析类 （csp_XXX → com.github.catovid.spider.XXX）。 实测上游登记的 307 个新站源里只有 28 条的解析类在本包里， 其余加进去端上只会多出一堆「解析器不存在」的死条目；
② 探测闸（动态）—— 真连一次确认接口有响应。探测不通会先问你 「仍要强行加入吗」，不点就不加；
③ 落盘闸 —— 通过后写进 data/added_sites.json，由 patch.build() 注入配置（不改 baseline 母本，换包也不丢）。
新加入的站点用独立 TAG（ADD_xxx），不与原版站点共用 TAG —— 上游常见「多个不同站共用一个解析类」（csp_TTian 同时是「追剧」和「天天」）， 共用 TAG 会让 A 站的地址被 B 站的域名顶掉。
端上要彻底退出 App 再打开才会看到新接口（App 只在启动时拉一次配置）。
为什么「新增一直是 0」：实测 8 个社区源里能找到的域名与池内完全重合 —— 这些网盘聚合站（玩偶/木偶/蜡笔/盘Ta…）根本不进公开 TVBox 配置，社区里翻来覆去就是同一份地址； 且 8 个源里只有 qist/tvbox 还在每天更新（其余最近一次推送是 2024 年）。
⇒ 真正会带来新地址的是两条：① 包内采集（作者发新版时把各站当前域名写进 js/*.js、lib/*.json，每次同步与每次换包都会扫）； ② 换 PG 包（新包自带作者在用的域名）。
判定按 key / api / 归一化站名 三维去重， 所以「玩偶→Wogg 换个写法」不会被误报成新站。

登录后获取 CK 步骤
  1. 点该行 ↗ 登录，在新窗口完成登录（扫码/账密都行）
  2. 登录成功后按 F12 打开开发者工具
  3. 切到 Network（网络）面板，按 F5 刷新页面
  4. 点左侧任意一条请求 → 右侧 Headers → Request Headers
  5. 找到 Cookie: 那一行，整行复制（别只复制一半）
  6. 粘进对应输入框 → 点 保存（保存后自动校验状态）
小技巧：装 Cookie-Editor 扩展，点开 → Export → 一键复制整串。
阿里云盘例外：它要的是 refresh_token（浏览器登录后在 F12 → Application → Local Storage 的 token 里取，或抓 auth.aliyuncs.com 的响应）。
失效判断：状态显示 失效 说明该 Cookie 过期，重新登录再贴一次即可。
