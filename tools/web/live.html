CK 同步 · 已废弃

⛔ CK 多端同步已于 2026-10-18 废弃
网盘凭据现在完全由 PG 原版机制管理：在 OK影视 里扫码登录，存在端上 /storage/emulated/0/TV/.<渠道>_user.pg，只对该设备生效。
中枢下发 lib/tokenm.json 的内容已恢复为原版模板原样（102 个字段 逐字一致），不再注入任何 CK / 代理，也不会覆盖端上你自己配的设置。
代理（YouTube 等）请在 App「网盘及弹幕配置」里按原版方式填写，由 PG 自己生效。
为什么放弃：① 凭据由 App 主程序保存（pg.jar 里搜 quark/webdav 命中 0），PG 包只是能"读"；② 壳给 JS 运行时的全局里没有文件 IO（只有 req/md5X/aesX/joinUrl），drpy2 的 readFile→os.open 在本壳无宿主实现； ③ 端对网盘 CK 只取不送（PUT 次数恒为 0），扫码登录也不触发任何 WebDAV 请求； ④ core_ok 红线不允许新增文件，没有合法的代码落点。
更要紧的是：中枢一旦有值就会覆盖端上刚登录好的状态 —— 风险远大于收益，故停用。
保留下来的：接口每日保活与失效自动修复（下面这些面板照常工作）。

外部中转 · 凭据旁路

…
原理：PG 的 tokenm.json 里 open_api_url 指向「网盘换 token 的接口」， 端会把扫码/刷新得到的凭据 POST 过去 —— 这一步本来直连第三方，中枢看不见。
改写开启后，该地址指向 /gw/ali/token：原样透传给真正的上游（端的功能不受影响）， 同时把请求与响应里的凭据截下来入库 → 其余设备下一轮拉配置（约 15~30 秒）就自动生效。

WebDAV 端点 · 端主动备份通道

…
WebDAV 通道已停用（2026-10-18），此处只保留只读观测。 回填与入库都已关闭：端来取 <渠道>.json 一律 404，它会继续用自己本地的 .pg 文件；端 PUT 上来的内容只落盘留档，不再解析进保险库。
保留这些记录的意义：万一日后还想再试，这堆日志就是判断"端到底会不会送"的唯一依据。
已知事实（实测）：端上的 CK 是明文文件 /storage/emulated/0/TV/.<渠道>_user.pg（例：夸克 .quark_user.pg）， 属外置存储、文件管理器可读可拷；而 网盘 CK 类 .json 的 PUT 次数恒为 0 —— 端只写过播放进度、连通测试、观影站点 cookie 三类。扫码登录本身也不触发任何 WebDAV 请求。
⇒ 结论：网盘请直接在 OK影视 里扫码登录，凭据只对该设备生效，不再追求多端共享。
